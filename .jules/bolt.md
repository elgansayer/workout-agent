## 2024-07-03 - SQLite Performance Tuning for Metric Dashboards
**Learning:** Found that the app stores dense historical metrics data (workouts, body metrics, individual exercise progress, daily logs) in SQLite arrays using the `database.py` file, but didn't index the `date` columns or standard filtering columns like `exercise_name`. These queries are run frequently (e.g. for retrieving best lifts or filtering by the current exercise and ordering by dates to render frontend graphs), leading to potential bottlenecks via full-table scans. Indexing the `date` column and the filtering columns correctly optimizes for these exact query workloads heavily reliant on time-series visualizations.
**Action:** Always check if columns used in heavy string or numerical ordering/filtering queries (like `date` or `exercise_name`) are properly indexed, especially since SQLite relies on B-Tree logic. Whenever creating new database structures serving dashbaords or graphical queries, insert corresponding indexing logic.
